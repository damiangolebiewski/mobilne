Blok 4. Walidacja danych i komunikaty

Faza I — wyrównanie W trakcie

Sprawdzasz dane z formularza kilkoma warunkami w ustalonej kolejności, porównujesz napisy poprawnie i wyświetlasz właściwy komunikat w obszarze komunikatów.

1. Cel

Po wykonaniu tego bloku będziesz potrafił:

  • zapisać ciąg warunków if / else if / else tak, aby komunikaty miały właściwy priorytet,
  • porównywać napisy metodą equals (a nie ==) i sprawdzać contains, length, isEmpty,
  • sprawdzić znak po znaku, czy tekst zawiera same cyfry (Character.isDigit),
  • wydzielić walidację do metody zwracającej komunikat (String) i pokazać go w obszarze komunikatów.

2. Krótkie przypomnienie

Priorytet komunikatów = kolejność warunków

Arkusz_01 wymaga: najpierw sprawdź e-mail, potem hasła, a gdy wszystko jest dobrze — powitanie. W kodzie to łańcuch else if: pierwszy spełniony warunek wygrywa.

Java
private String sprawdz(String email, String haslo, String haslo2) {
    if (!email.contains("@")) {
        return "Nieprawidłowy adres e-mail";
    } else if (!haslo.equals(haslo2)) {
        return "Hasła się różnią";
    } else {
        return "Witaj " + email;
    }
}
// w obsłudze przycisku:
tvKomunikat.setText(sprawdz(email, haslo, haslo2));

Obszar komunikatów

W XML nadaj mu tekst startowy z polecenia — często „Autor: <numer zdającego>”. Po kliknięciu nadpisujesz go komunikatem.

Ćwiczenie natychmiastowe: w przykładzie poniżej dopisz warunek „wiek > 120 → Nieprawidłowy wiek” na końcu łańcucha zamiast na początku. Wpisz 150. Co się wyświetla i dlaczego?

package com.example.egzamin;

import android.os.Bundle;
import android.widget.Button;
import android.widget.EditText;
import android.widget.TextView;

import androidx.appcompat.app.AppCompatActivity;

public class MainActivity extends AppCompatActivity {

    private EditText etWiek;
    private TextView tvKomunikat;

    @Override
    protected void onCreate(Bundle savedInstanceState) {
        super.onCreate(savedInstanceState);
        setContentView(R.layout.activity_main);

        etWiek = findViewById(R.id.etWiek);
        tvKomunikat = findViewById(R.id.tvKomunikat);
        Button btnSprawdz = findViewById(R.id.btnSprawdz);

        btnSprawdz.setOnClickListener(v -> tvKomunikat.setText(ocenWiek(etWiek.getText().toString().trim())));
    }

    // Walidacja w osobnej metodzie: dostaje tekst, zwraca komunikat.
    // Kolejność warunków = priorytet komunikatów.
    private String ocenWiek(String tekst) {
        if (tekst.isEmpty()) {
            return "Podaj wiek";
        }
        int wiek = Integer.parseInt(tekst);    // bezpieczne: inputType="number" i pole niepuste
        if (wiek > 120) {
            return "Nieprawidłowy wiek";
        } else if (wiek < 18) {
            return "Niepełnoletni";
        } else {
            return "Pełnoletni";
        }
    }
}

Zwróć uwagę na maxLength="3" w XML: dzięki niemu parseInt nie dostanie zbyt długiej liczby.

4. Mikroćwiczenia

Ćwiczenie 4.1 — equals czy ==

Które warunki są poprawne? a) if (kod == "1234") b) if (kod.equals("1234")) c) if ("1234".equals(kod)) d) if (kod.length() == 4)

Sprawdź odpowiedź

Poprawne: b, c, d. Porównanie liczb (length() == 4) przez == jest dobre; porównanie napisów — tylko equals. Wariant c) nie rzuci wyjątku, nawet gdy kod jest null.

Ćwiczenie 4.2 — Kolejność warunków

Java
if (haslo.length() < 6) return "Hasło za krótkie";
else if (haslo.isEmpty()) return "Podaj hasło";
else return "OK";

Użytkownik nic nie wpisał. Jaki komunikat zobaczy? Czy o to chodziło? Popraw.

Sprawdź odpowiedź

„Hasło za krótkie” — pusty tekst ma długość 0 < 6, więc pierwszy warunek wygrywa. Najpierw sprawdzaj przypadek najbardziej szczegółowy (puste pole), potem długość.

Ćwiczenie 4.3 — Same cyfry

Napisz metodę boolean czySameCyfry(String tekst), która zwraca true, gdy każdy znak jest cyfrą.

Sprawdź odpowiedź
Java
private boolean czySameCyfry(String tekst) {
    for (int i = 0; i < tekst.length(); i++) {
        if (!Character.isDigit(tekst.charAt(i))) {
            return false;
        }
    }
    return true;
}

Ćwiczenie 4.4 — Zakres

Zapisz warunek: „liczba należy do przedziału ⟨1, 12⟩”. Potem zapisz warunek przeciwny (liczba spoza przedziału) na dwa sposoby.

Sprawdź odpowiedź

n >= 1 && n <= 12. Przeciwny: n < 1 || n > 12 albo !(n >= 1 && n <= 12).

Ćwiczenie 4.5 — Komunikat z danymi

Po poprawnej walidacji wyświetl „Witaj anna@poczta.pl” (Arkusz_01), gdzie adres pochodzi z pola etEmail. Napisz jedną linię.

Sprawdź odpowiedź

tvKomunikat.setText("Witaj " + etEmail.getText().toString().trim());

5. Zadanie prowadzone

Sprawdzanie kodu pocztowego

⏱ ok. 40 min

Wzorzec walidacji z zadania desktopowego (Arkusz_06) przeniesiony do aplikacji mobilnej: kod ma mieć dokładnie 5 znaków i składać się z samych cyfr.

Komunikaty (w tej kolejności):

  1. długość różna od 5 → „Nieprawidłowa liczba znaków w kodzie”,
  2. przynajmniej jeden znak nie jest cyfrą → „Kod może zawierać tylko cyfry”,
  3. w przeciwnym razie → „Kod poprawny: 06-100” (myślnik wstaw po dwóch pierwszych cyfrach).

Pole ma celowo inputType="text", żeby dało się wpisać literę i przetestować drugi komunikat.

Kroki:

  1. XML: tytuł, EditText, przycisk wyśrodkowany, napis komunikatu.
  2. Metoda boolean czySameCyfry(String tekst).
  3. Metoda String sprawdzKod(String kod) zwracająca komunikat.
  4. Obsługa przycisku: odczyt, trim, setText(sprawdzKod(kod)).
  5. Testy: 0610, 061000, 06l00, 06100.

Pomoc — otwieraj po kolei i tylko wtedy, gdy utkniesz:

Poziom 1 — kierunek

Najpierw długość, potem cyfry. Metoda zwracająca String może kończyć się return w każdym warunku — nie potrzeba wtedy else.

Poziom 2 — konkretna wskazówka

Formatowanie: kod.substring(0, 2) + "-" + kod.substring(2) → „06” + „-” + „100”.

Poziom 3 — pseudokod / struktura
Tekst
sprawdzKod(kod):
    jeśli długość ≠ 5        → zwróć "Nieprawidłowa liczba znaków w kodzie"
    jeśli nie same cyfry     → zwróć "Kod może zawierać tylko cyfry"
    zwróć "Kod poprawny: " + pierwsze 2 znaki + "-" + reszta
Poziom 4 — fragment implementacji
Java
private String sprawdzKod(String kod) {
    if (kod.length() != 5) {
        return "Nieprawidłowa liczba znaków w kodzie";
    }
    if (!czySameCyfry(kod)) {
        return "Kod może zawierać tylko cyfry";
    }
    return "Kod poprawny: " + kod.substring(0, 2) + "-" + kod.substring(2);
}

6. Zadanie samodzielne

Bankomat: PIN i trzy próby

⏱ ok. 35 min

Walidacja z pamięcią: aplikacja liczy nieudane próby i po trzeciej blokuje przycisk.

  • Poprawny PIN to 2468 (stała w kodzie). Pole ukrywa cyfry i przyjmuje maksymalnie 4 znaki.
  • Na starcie napis „Pozostało prób: 3”.
  • PIN o długości innej niż 4 → „PIN musi mieć 4 cyfry” (to nie zużywa próby).
  • Poprawny PIN → „Zalogowano”, przycisk przestaje działać.
  • Błędny PIN → pole się czyści, „Błędny PIN. Pozostało prób: n”; po trzeciej błędnej próbie „Karta zablokowana” i przycisk przestaje działać.

Pomoc — otwieraj po kolei i tylko wtedy, gdy utkniesz:

Poziom 1 — kierunek

Potrzebujesz pola klasy z liczbą nieudanych prób. Przycisk wyłączysz metodą, którą poznasz dokładniej w bloku 7: setEnabled(false).

Poziom 2 — konkretna wskazówka

Pole: android:inputType="numberPassword" i android:maxLength="4". Porównanie: pin.equals(POPRAWNY_PIN). Czyszczenie pola: etPin.setText("").

Poziom 3 — pseudokod / struktura
Tekst
sprawdzPin():
    jeśli długość ≠ 4 → komunikat; zakończ
    jeśli PIN poprawny → "Zalogowano"; wyłącz przycisk; zakończ
    nieudane++ ; wyczyść pole
    jeśli nieudane >= 3 → "Karta zablokowana"; wyłącz przycisk
    inaczej → "Błędny PIN. Pozostało prób: " + (3 − nieudane)
Poziom 4 — fragment implementacji
Java
nieudaneProby++;
etPin.setText("");
if (nieudaneProby >= LIMIT_PROB) {
    tvKomunikat.setText("Karta zablokowana");
    btnZaloguj.setEnabled(false);
} else {
    tvKomunikat.setText("Błędny PIN. Pozostało prób: " + (LIMIT_PROB - nieudaneProby));
}

package com.example.egzamin;

import android.os.Bundle;
import android.widget.Button;
import android.widget.EditText;
import android.widget.TextView;

import androidx.appcompat.app.AppCompatActivity;

public class MainActivity extends AppCompatActivity {

    private static final String POPRAWNY_PIN = "2468";
    private static final int LIMIT_PROB = 3;

    private int nieudaneProby = 0;
    private EditText etPin;
    private TextView tvKomunikat;
    private Button btnZaloguj;

    @Override
    protected void onCreate(Bundle savedInstanceState) {
        super.onCreate(savedInstanceState);
        setContentView(R.layout.activity_main);

        etPin = findViewById(R.id.etPin);
        tvKomunikat = findViewById(R.id.tvKomunikat);
        btnZaloguj = findViewById(R.id.btnZaloguj);

        btnZaloguj.setOnClickListener(v -> sprawdzPin());
    }

    private void sprawdzPin() {
        String pin = etPin.getText().toString();
        if (pin.length() != 4) {
            tvKomunikat.setText("PIN musi mieć 4 cyfry");
            return;
        }
        if (pin.equals(POPRAWNY_PIN)) {
            tvKomunikat.setText("Zalogowano");
            btnZaloguj.setEnabled(false);
            return;
        }
        nieudaneProby++;
        etPin.setText("");
        if (nieudaneProby >= LIMIT_PROB) {
            tvKomunikat.setText("Karta zablokowana");
            btnZaloguj.setEnabled(false);
        } else {
            tvKomunikat.setText("Błędny PIN. Pozostało prób: " + (LIMIT_PROB - nieudaneProby));
        }
    }
}

7. Zadanie w stylu INF.04

Aktywacja karty miejskiej

⏱ ok. 45 min

Wykonaj aplikację mobilną do aktywacji karty miejskiej i uruchom ją w emulatorze.

Krok 1–6: analiza polecenia. Zanim otworzysz Android Studio, wypisz na kartce (lub w komentarzu) odpowiedzi:
INTERFEJSCo musi znaleźć się na ekranie?
DANECo wpisuje / wybiera użytkownik?
ZDARZENIACo uruchamia działania?
LOGIKACo trzeba policzyć / sprawdzić / zmienić?
WYNIKCo aplikacja wyświetla lub zmienia?
WYGLĄDKolory, rozmiary, marginesy, rozkłady?
Porównaj swoją analizę z wzorcową
INTERFEJStytuł, 3 etykiety, 3 pola edycyjne, przycisk, obszar komunikatów
DANEnumer karty (cyfry), PIN i powtórzony PIN (ukryte cyfry)
ZDARZENIAkliknięcie „AKTYWUJ”
LOGIKA4 warunki w kolejności: długość numeru 8, długość PIN 4, równość PIN-ów (equals), PIN nie z 4 identycznych cyfr
WYNIKjeden z 5 komunikatów; na starcie „Autor: <numer>”
WYGLĄDtytuł #6A1B9A biały, największy; pola na całą szerokość z marginesem 10; przycisk #6A1B9A wyśrodkowany; komunikat wyśrodkowany

Elementy aplikacji:

  • Napis „Karta miejska”.
  • Napis „Numer karty:”, a pod nim pole edycyjne z podpowiedzią „8 cyfr”, przyjmujące tylko cyfry.
  • Napis „PIN:”, a pod nim pole edycyjne z podpowiedzią „4 cyfry” — ukrywa wpisywane cyfry.
  • Napis „Powtórz PIN:”, a pod nim pole jak wyżej.
  • Przycisk „AKTYWUJ” (wyśrodkowany).
  • Obszar do wyświetlania komunikatów (wyśrodkowany); na początku działania aplikacji wyświetla „Autor: ”, dalej numer zdającego.

Działanie aplikacji: po wybraniu „AKTYWUJ” sprawdzane są kolejno warunki i wyświetlany jest pierwszy pasujący komunikat:

  1. numer karty nie ma dokładnie 8 znaków → „Numer karty musi mieć 8 cyfr”,
  2. PIN nie ma dokładnie 4 znaków → „PIN musi mieć 4 cyfry”,
  3. PIN różni się od powtórzonego PIN-u → „PIN-y są różne”,
  4. PIN składa się z czterech jednakowych cyfr (np. 1111) → „PIN jest zbyt prosty”,
  5. brak błędów → „Karta <numer> aktywna”, gdzie <numer> to wpisany numer karty.

Założenia aplikacji:

  • Interfejs w XML, rozkład liniowy pionowy.
  • Tytuł: tło #6A1B9A, biała czcionka, rozmiar największy, marginesy wewnętrzne 10.
  • Pola edycyjne rozciągnięte na szerokość ekranu (margines boczny 10). Przycisk: tło #6A1B9A, biała czcionka.
  • Sprawdzanie danych zrealizuj w osobnej metodzie zwracającej treść komunikatu.

Checklista zadania

Pomoc — otwieraj po kolei i tylko wtedy, gdy utkniesz:

Poziom 1 — kierunek

Napisz najpierw metodę sprawdzDane(numer, pin, pin2) z łańcuchem if / else if. Obsługa przycisku ma tylko odczytać pola i wywołać tę metodę.

Poziom 2 — konkretna wskazówka

„Cztery jednakowe cyfry”: porównaj każdy znak z pierwszym (charAt(i) != charAt(0)). Znaki (char) można porównywać przez ==/!=.

Poziom 3 — pseudokod / struktura
Tekst
sprawdzDane(numer, pin, pin2):

package com.example.egzamin;

import android.os.Bundle;
import android.widget.Button;
import android.widget.EditText;
import android.widget.TextView;

import androidx.appcompat.app.AppCompatActivity;

public class MainActivity extends AppCompatActivity {

    private EditText etNumer, etPin, etPin2;
    private TextView tvKomunikat;

    @Override
    protected void onCreate(Bundle savedInstanceState) {
        super.onCreate(savedInstanceState);
        setContentView(R.layout.activity_main);

        etNumer = findViewById(R.id.etNumer);
        etPin = findViewById(R.id.etPin);
        etPin2 = findViewById(R.id.etPin2);
        tvKomunikat = findViewById(R.id.tvKomunikat);
        Button btnAktywuj = findViewById(R.id.btnAktywuj);

        btnAktywuj.setOnClickListener(v -> {
            String numer = etNumer.getText().toString().trim();
            String pin = etPin.getText().toString();
            String pin2 = etPin2.getText().toString();
            tvKomunikat.setText(sprawdzDane(numer, pin, pin2));
        });
    }

    // Warunki sprawdzane w kolejności z polecenia — pierwszy niespełniony decyduje o komunikacie.
    private String sprawdzDane(String numer, String pin, String pin2) {
        if (numer.length() != 8) {
            return "Numer karty musi mieć 8 cyfr";
        } else if (pin.length() != 4) {
            return "PIN musi mieć 4 cyfry";
        } else if (!pin.equals(pin2)) {
            return "PIN-y są różne";
        } else if (czyTeSameZnaki(pin)) {
            return "PIN jest zbyt prosty";
        } else {
            return "Karta " + numer + " aktywna";
        }
    }

    private boolean czyTeSameZnaki(String tekst) {
        for (int i = 1; i < tekst.length(); i++) {
            if (tekst.charAt(i) != tekst.charAt(0)) {
                return false;
            }
        }
        return true;
    }
}

Silniejszy PIN

Dodaj warunek: PIN nie może być ciągiem rosnącym (1234, 2345 …). Komunikat „PIN jest zbyt prosty”.

Wskazówka

Dla każdego i od 1: tekst.charAt(i) == tekst.charAt(i - 1) + 1. Znak + 1 daje liczbę (kod znaku), porównanie z char działa.
